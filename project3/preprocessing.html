The Importance of Preprocessing

Client Side vs Server Side Preprocessing

Client side preprocessing occurs when a stylesheet written in SASS, SCSS, or LESS. SASS, SCSS, and LESS are all programs that can be used with CSS. If and when CSS files get longer and more complex, you can use one of these programs to write a short hand version of CSS. It compiles into CSS when an HTML file is run, like a normal stylesheet. The difference is when it actually runs.

On a server-side preprocessed file, that means it's already been compiled into CSS when the user activates the page, by the server. A client-side proeprocess means that when the HTML page is accessed, the server send the SASS, SCSS, or LESS page to the client's processor and converts it to CSS then, when it reaches their computer.


SASS Mechanisms


SASS Basics

Variables

The variables in SASS are represented by the $ sign. You can make variables in SASS and call them later as you write, which is very helpful, as it can be changed in one place and trickle down as opposed to having to change things in a dozen different places.

Nesting Hierarchy

In CSS, there isn't a hierachy, or any kind of nesting. It's simply all on the same line. In SASS, you can make nested hierarchies, and nest specific items such as li and li:a, they can be listed underneath each other and use the same parameters without having to repeat each part and rewrite them constantly.

Mixins

Mixins are similar to the above variables, where they can be listed at the top of the SASS page and used throughout the file, being called when they need to be used.
